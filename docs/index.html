把 sing-box 做成
一台可运维的设备

面板不是官方 Dashboard 的复刻，也不是另一个配置生成器。它是一个 20 MB 以内的控制面： 只负责模板合并、进程生命周期、鉴权，以及把 sing-box 原生 API 安全地转给浏览器。 所有路由语义留在 sing-box 自己手里。

目标设备 MT7981B · 256 MB 常驻内存 ≤ 20 MB 交付 单二进制 + embed 存储 JSON + rename

00一页纸架构

一句话概括：面板是 sing-box 的薄控制面，不是它的配置编译器。 配置语义迭代交给上游，面板只维护「模板 + 节点片段 + 用户覆盖」三层 JSON 的合并关系， 并在每次写入前用 sing-box check 做唯一权威校验。

五条设计原则

  1. 语义下沉。面板不硬编码任何 sing-box 字段映射。模板由用户维护，节点片段由订阅解析产出，合并只做 JSON 层的 key 覆盖与数组拼接。
  2. 内存有上限，而不是「尽量少」。Go 堆 6–8 MB、日志 50 行环形缓冲、延迟结果 36×32 B、连接列表 200 条封顶。每一项都有明确的数字预算。
  3. 写前必校验，失败必回滚。check 是唯一权威；写入走 tmp → fsync → rename；重载失败自动回到上一快照。
  4. 实时数据不落盘。延迟、连接、流量全部只存在于内存与 WebSocket，进程重启即清零。
  5. 默认安全。监听 127.0.0.1:9090，Bearer Token 无 Cookie，危险操作二次确认，tproxy 需显式选择。
与 v2rayA 的关系：借鉴它的用户流程（订阅 → 节点 → 一键透明代理 → 连接观测）， 但不复刻它的配置生成架构（后端拼装完整配置 + RoutingA 方言）。本面板的输出永远是原生 sing-box JSON。

01模块划分

后端按「HTTP 边界 / 业务能力 / 存储原语」三层切分。handler 不写业务，service 不碰 http.ResponseWriter， store 只提供原子读写。每个包都对应一条硬约束。

包职责对应约束
cmd/panel启动、flag、优雅退出；设置 GOMEMLIMIT 与信号处理二 · 常驻内存
internal/httpapi路由、鉴权中间件、结构化错误、WS 升级三 · 后端四件事
internal/service/config模板合并、check、快照轮转、apply / rollback三-1 / 三-4 / 三-5

前端不引入任何 UI 组件库与状态库。Svelte 编译产物直接操作 DOM，运行时只有一份约 40 KB 的调度代码：

  • src/lib/api.ts — 唯一 fetch 出口，负责 Bearer Token、错误归一化。
  • src/lib/ws.ts — WebSocket 封装，指数退避重连（1s → 30s 封顶）。
  • src/lib/stores/ — 只用 Svelte 原生 store，按领域拆分：nodes / service / config。
  • src/routes/ — 每个页面一个目录，SvelteKit 默认按路由懒加载。

02数据流

A · 订阅 → 节点片段

POST /api/v1/subscriptions/{id}/refresh 触发。fetcher 用 15s 超时、8 MB 上限读取响应； parser 依次尝试 Clash YAML、Base64 节点列表、sing-box outbounds 三种格式；归一化后写入 outbounds.frag.json（原子写）。原始响应只在函数栈上存活，返回即被 GC。 订阅 URL 使用 AES-GCM 加密后存入 subs.json，日志仅输出掩码。

B · 配置写入（最关键的一条链路）

六步，任何一步失败都不会留下半截配置。校验进程与运行进程分离，写入与重载分离，回滚是独立能力而不是异常分支里的补丁。

apply 全程持有单飞锁；check 与 reload 之间不允许并发第二次 apply

C · 实时数据（浏览器 ← 面板 ← Clash API）

浏览器连接 /api/v1/ws/connections，面板在服务端建立到 127.0.0.1:9091/connections 的 WebSocket，读取后做三件事： 裁剪字段（只保留 host / chain / rule / up / down / start）、截断到 200 条、 按 2 秒节流只转发最新一帧。中间帧直接丢弃，不排队，避免弱 CPU 上堆积。 整条链路没有任何磁盘写入。

节流的实现位置很关键。如果在前端节流，后端仍要把每帧 JSON 序列化并推过 socket； 在路由器上，序列化 200 条连接的峰值分配比网络传输更贵。因此节流必须发生在服务端读取循环里。

04单二进制与体积预估

目标：scp panel root@router:/usr/bin/ 之后即可运行，不依赖 Node、不依赖 systemd、不额外起进程。 前端产物通过 embed 编进 rodata 段，http.FileServer 读取时直接引用这段只读内存， 不会把 400 KB 静态资源复制进 Go 堆。

组成大小说明
Go runtime + net/http + crypto/tls6.6 MBarm64，-ldflags="-s -w"
业务代码（handler / service / store）1.9 MB无 ORM、无模板引擎、无第三方路由库
前端静态资源（embed）0.42 MBSvelte 编译产物；gzip 后约 110 KB
图标与字体0.02 MB内联 SVG sprite，不打包字体文件
合计≈ 9.1 MB与 sing-box 本体（约 10 MB）同量级
不建议在 256 MB 设备上使用 UPX。UPX 能把体积压到 3.6 MB，但运行时需要把整个镜像解压到匿名内存， 相当于用 5 MB 磁盘 换 9 MB 常驻内存，还会增加约 80 ms 启动时间。Flash 紧张时优先裁剪前端， 而不是压缩二进制。

embed 的写法

web/embed.gogo
package web

import (
	"embed"
	"io/fs"
	"net/http"
	"strings"
)

// dist 由 `pnpm build` 产出：adapter-static，ssr=false，prerender=false。
// 约束 二：前端必须是纯静态资源，运行时零 Node。
//
//go:embed all:dist
var dist embed.FS

// Handler 让同一个 Go 进程同时承担 API 与静态资源，不引入第二个常驻进程。
func Handler() (http.Handler, error) {
	sub, err := fs.Sub(dist, "dist")
	if err != nil {
		return nil, err
	}
	files := http.FileServer(http.FS(sub))

	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// 带内容哈希的产物可以长缓存，index.html 必须每次回源。
		if strings.HasPrefix(r.URL.Path, "/_app/immutable/") {
			w.Header().Set("Cache-Control", "public, max-age=31536000, immutable")
		} else {
			w.Header().Set("Cache-Control", "no-cache")
		}
		// SPA 回退：非静态资源路径一律返回 index.html
		if !strings.Contains(r.URL.Path, ".") {
			r.URL.Path = "/"
		}
		files.ServeHTTP(w, r)
	}), nil
}

6.1 原子写入 · 约束 五（JSON + 原子写，单文件 ≤ 100 KB）

internal/store/atomic.gogo
package store

import (
	"encoding/json"
	"fmt"
	"os"
	"path/filepath"
)

const maxFileSize = 100 << 10 // 约束：单文件 100 KB 上限

// WriteJSON 以 tmp → fsync → rename 的方式落盘。
// 断电时要么是旧文件，要么是新文件，永远不会出现半截 JSON。
func WriteJSON(path string, v any) error {
	b, err := json.MarshalIndent(v, "", "  ")
	if err != nil {
		return fmt.Errorf("marshal %s: %w", filepath.Base(path), err)
	}
	if len(b) > maxFileSize {
		return fmt.Errorf("%s exceeds 100KB budget: %d bytes",
			filepath.Base(path), len(b))
	}

	tmp, err := os.CreateTemp(filepath.Dir(path), ".tmp-*")
	if err != nil {
		return fmt.Errorf("create temp: %w", err)
	}
	defer os.Remove(tmp.Name()) // rename 成功后这里是 no-op

	if _, err = tmp.Write(b); err != nil {
		tmp.Close()
		return err
	}
	if err = tmp.Sync(); err != nil { // 关键：先把数据刷到 flash
		tmp.Close()
		return err
	}
	if err = tmp.Close(); err != nil {
		return err
	}
	// 同目录 rename 在同一文件系统内是原子操作。
	return os.Rename(tmp.Name(), path)
}

6.2 校验 → 快照 → 写入 → 回滚 · 约束 三-4、三-5

internal/service/config/apply.gogo
package config

// Applier 全程单飞：check 与 reload 之间不允许并发第二次 apply，
// 否则两次 check 进程叠加会在 256MB 设备上触发 OOM killer。
type Applier struct {
	mu       sync.Mutex
	bin      string // /usr/bin/sing-box
	confPath string // /etc/sing-box/config.json
	snapDir  string // /etc/sing-box/snapshots
	keep     int    // 默认 3，可配置
	reload   func() error
	probe    func(ctx context.Context) error // GET /version
}

func (a *Applier) Apply(ctx context.Context, raw []byte) error {
	a.mu.Lock()
	defer a.mu.Unlock()

	// 1. 语法校验：check 是唯一权威，面板不做字段级校验。
	if err := a.check(ctx, raw); err != nil {
		return &CheckError{Detail: err.Error()} // handler 原样回传给前端
	}
	// 2. 快照当前版本（保留最近 keep 份，默认 3）。
	if err := a.snapshot(); err != nil {
		return fmt.Errorf("snapshot: %w", err)
	}
	// 3. 原子替换。
	if err := store.WriteFileAtomic(a.confPath, raw, 0o600); err != nil {
		return fmt.Errorf("write config: %w", err)
	}
	// 4. 重载并探活；失败则回滚，绝不停在一个起不来的配置上。
	if err := a.reload(); err != nil {
		return a.rollbackAndReport(ctx, err)
	}
	probeCtx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	if err := a.probe(probeCtx); err != nil {
		return a.rollbackAndReport(ctx, err)
	}
	return nil
}

func (a *Applier) check(ctx context.Context, raw []byte) error {
	f, err := os.CreateTemp("", "sb-check-*.json")
	if err != nil {
		return err
	}
	defer os.Remove(f.Name())
	if _, err := f.Write(raw); err != nil {
		f.Close()
		return err
	}
	f.Close()

	ctx, cancel := context.WithTimeout(ctx, 8*time.Second)
	defer cancel()

	cmd := exec.CommandContext(ctx, a.bin, "check", "-c", f.Name())
	// check 是独立进程，单独限内存，避免它把整机拖垮。
	cmd.Env = append(os.Environ(), "GOMEMLIMIT=32MiB")

	out, err := cmd.CombinedOutput()
	if err != nil {
		return fmt.Errorf("%s", strings.TrimSpace(string(out)))
	}
	return nil
}

func (a *Applier) rollbackAndReport(ctx context.Context, cause error) error {
	if rbErr := a.Rollback(ctx); rbErr != nil {
		return fmt.Errorf("apply failed (%v) and rollback failed: %w", cause, rbErr)
	}
	return fmt.Errorf("apply failed, rolled back to previous snapshot: %w", cause)
}

6.3 进程管理 + 50 行环形日志 · 约束 四 · P0 服务控制

internal/service/supervisor/process.gogo
package supervisor

const logCapacity = 50 // 约束：只保留最近 50 行，且只在内存

type Supervisor struct {
	mu     sync.Mutex
	cmd    *exec.Cmd
	ring   *Ring[LogLine] // 固定 50 槽，写满覆盖最旧
	onExit func(error)
}

func (s *Supervisor) Start() error {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.cmd != nil {
		return ErrAlreadyRunning
	}

	cmd := exec.Command(s.bin, "run", "-c", s.confPath)
	// 独立进程组：Stop 时能连同子进程一起收掉。
	cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}

	stdout, err := cmd.StdoutPipe()
	if err != nil {
		return err
	}
	cmd.Stderr = cmd.Stdout // 合并，避免两个 reader goroutine

	if err := cmd.Start(); err != nil {
		return fmt.Errorf("start sing-box: %w", err)
	}
	s.cmd = cmd
	go s.pump(stdout)
	go func(c *exec.Cmd) {
		err := c.Wait()
		s.mu.Lock()
		s.cmd = nil
		s.mu.Unlock()
		if s.onExit != nil {
			s.onExit(err)
		}
	}(cmd)
	return nil
}

// pump 用固定大小 scanner 读取，超长行截断而不是扩容。
// 每行只进 ring buffer，不写文件、不写 channel（无消费者时不阻塞）。
func (s *Supervisor) pump(r io.Reader) {
	sc := bufio.NewScanner(r)
	sc.Buffer(make([]byte, 4096), 16<<10)
	for sc.Scan() {
		s.ring.Push(LogLine{
			At:  time.Now(),
			Raw: sc.Text(),
		})
	}
}

6.4 Clash API 反代 + 服务端节流 · 约束 三-3、六 · WebSocket

internal/httpapi/clashproxy.gogo
// connections 把 Clash API 的 WS 转给浏览器，但做三件事：
// 裁剪字段、截断 200 条、2 秒节流（只转发最新帧）。
// 约束 三-3：后端不做业务重写；约束 四-P1：连接列表不落盘。
func (h *Handler) connections(w http.ResponseWriter, r *http.Request) {
	up, err := h.clash.DialWS(r.Context(), "/connections")
	if err != nil {
		writeErr(w, http.StatusBadGateway, "clash_unreachable", err.Error())
		return
	}
	defer up.Close()

	down, err := h.upgrader.Upgrade(w, r, nil)
	if err != nil {
		return
	}
	defer down.Close()

	var latest atomic.Pointer[[]byte]
	go func() { // 读取循环：只保留最新一帧，中间帧直接丢弃
		for {
			_, msg, err := up.ReadMessage()
			if err != nil {
				return
			}
			frame := trimConnections(msg, 200)
			latest.Store(&frame)
		}
	}()

	ticker := time.NewTicker(2 * time.Second) // 弱 CPU 上 2s 足够
	defer ticker.Stop()

	for {
		select {
		case <-r.Context().Done():
			return
		case <-ticker.C:
			if p := latest.Swap(nil); p != nil {
				if err := down.WriteMessage(websocket.TextMessage, *p); err != nil {
					return
				}
			}
		}
	}
}

// trimConnections 只保留前端真正渲染的字段，体积约为原始帧的 1/4。
func trimConnections(raw []byte, limit int) []byte {
	var in struct {
		Connections []struct {
			ID    string   `json:"id"`
			Meta  struct {
				Host       string `json:"host"`
				DestinationIP string `json:"destinationIP"`
				Network    string `json:"network"`
			} `json:"metadata"`
			Chains []string `json:"chains"`
			Rule   string   `json:"rule"`
			Upload   int64  `json:"upload"`
			Download int64  `json:"download"`
			Start    string `json:"start"`
		} `json:"connections"`
	}
	if json.Unmarshal(raw, &in) != nil {
		return []byte(`{"connections":[]}`)
	}
	if len(in.Connections) > limit {
		in.Connections = in.Connections[:limit]
	}
	out, _ := json.Marshal(in) // 复用 encoder 可进一步省分配
	return out
}

6.5 订阅拉取：原始响应不落盘 · 约束 四 · P0 订阅

// Refresh 拉取订阅并解析为 outbound 片段。
// body 只在本次调用内存在：解析完即被 GC，不写磁盘、不进缓存。
func (s *Service) Refresh(ctx context.Context, id string) (Result, error) {
	sub, err := s.store.Get(id)
	if err != nil {
		return Result{}, err
	}

	ctx, cancel := context.WithTimeout(ctx, 15*time.Second)
	defer cancel()

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, sub.URL, nil)
	if err != nil {
		return Result{}, err
	}
	req.Header.Set("User-Agent", "sing-box-panel/0.9")

	resp, err := s.client.Do(req)
	if err != nil {
		return Result{}, fmt.Errorf("fetch: %w", err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return Result{}, fmt.Errorf("upstream %d", resp.StatusCode)
	}

	// 8MB 硬上限：恶意订阅不能把 256MB 的设备打爆。
	body, err := io.ReadAll(io.LimitReader(resp.Body, 8<<20))
	if err != nil {
		return Result{}, err
	}

	nodes, err := parse(body, resp.Header.Get("Content-Type"))
	if err != nil {
		return Result{}, fmt.Errorf("parse: %w", err)
	}

	// 只持久化解析结果；sub.URL 加密后写回 subs.json。
	if err := s.store.SaveNodes(id, nodes); err != nil {
		return Result{}, err
	}
	return Result{Count: len(nodes)}, nil // body 到此为止
}

async function req<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(path, {
    ...init,
    headers: {
      'content-type': 'application/json',
      ...(token ? { authorization: `Bearer ${token}` } : {}),
      ...init.headers
    }
  });

  if (res.status === 401) {
    token = '';
    localStorage.removeItem('sb_token');
    throw new ApiError(401, 'unauthorized');
  }
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new ApiError(res.status, body.error ?? 'unknown', body.detail);
  }
  return res.status === 204 ? (undefined as T) : res.json();
}

6.7 Svelte · 节点 store（TTL + 并发测速）

web/src/lib/stores/nodes.tsts
import { writable, get } from 'svelte/store';
import { api } from '$lib/api';

export type Latency = { ms: number; at: number };
const TTL = 5 * 60_000; // 约束 四-P0：延迟结果 5 分钟过期，且不落盘

export const nodes = writable<Node[]>([]);
export const latency = writable<Record<string, Latency>>({});

export async function loadNodes() {
  nodes.set(await api.nodes());
}

/** 前端也限制 3 并发，避免把弱 CPU 的请求队列打满；
 *  服务端还有一层 semaphore(3) 兜底。 */
export async function testAll(tags: string[]) {
  const queue = [...tags];
  const worker = async () => {
    for (let tag = queue.shift(); tag; tag = queue.shift()) {
      const started = Date.now();
      const ms = await api.delayOne(tag);
      latency.update((m) => ({ ...m, [tag]: { ms, at: started } }));
    }
  };
  await Promise.all([worker(), worker(), worker()]);
}

/** 读取时顺手做过期判断，避免定时器在后台常驻。 */
export function fresh(tag: string): number | undefined {
  const hit = get(latency)[tag];
  if (!hit) return undefined;
  return Date.now() - hit.at > TTL ? undefined : hit.ms;
}

07MT7981 上最容易 OOM / 启动失败的 5 个点

256 MB 的机器上，真正危险的不是面板本身，而是面板允许用户打开的那些开关。 以下五条按发生概率排序，每条都给出可执行的数值与配置项。

R1

tproxy 全量接管：单点就能吃掉 200 MB

OOM

社区实测：v2rayA 在 OpenWrt 上启用 tproxy 后 RSS 升至 219 MB 并触发 OOM，切回 redirect 后正常。 原因是 tproxy 需要 mangle 表 + 策略路由 + UDP conntrack，QUIC/P2P 场景下 conntrack 条目会指数增长。

本机预算：系统与 dnsmasq 约 60 MB、sing-box 约 40 MB、面板 14 MB，可用余量仅 96 MB。

规避

① 默认只提供 redirect；tproxy 必须二次确认并显示风险文案。
② 限制 conntrack 表：nf_conntrack_max=16384，UDP 超时压到 30s。
③ 面板每 10s 读取 /proc/sys/net/netfilter/nf_conntrack_count，超过 80% 自动降级回 redirect 并告警。

/etc/sysctl.d/99-singbox.confsh
net.netfilter.nf_conntrack_max = 16384
net.netfilter.nf_conntrack_udp_timeout = 30
net.netfilter.nf_conntrack_udp_timeout_stream = 60
# 不要为了 tproxy 调大 rmem，那会直接把内存送给 socket 缓冲
net.core.rmem_max = 212992
R2

Geo 数据与 rule_set 全量加载：静默吃掉 20–60 MB

OOM

使用旧字段 geosite / geoip 时，sing-box 会把整个 geosite.db（约 4.5 MB） 与 geoip.db（约 5 MB）读入并解析成内存结构，峰值可放大到 20–60 MB。 叠加 cache_file.store_rdrc=true 后，规则集缓存还会同时占内存和 flash。

规避

① 一律使用 rule_set + format: binary，只下载真正用到的 3–5 个集合（单个 300–900 KB）。
② 关闭 store_rdrc，只保留 cache_file.enabled 用于 selected outbound。
③ 面板只编辑规则条目，永远不把 Geo 数据传给前端解析。

R3

Go 运行时没有内存上限：堆会翻倍

OOM

默认 GOGC=100 意味着堆增长到上次 GC 后的 2 倍才回收。面板稳态堆 6.4 MB， 峰值可到 13 MB，加上 goroutine 栈、socket 缓冲与 mmap，RSS 轻松突破 25 MB——超出 20 MB 预算。

规避

① 启动时 debug.SetMemoryLimit(16 << 20)，并设 GOGC=40。
② HTTP server 限死头部与超时；WS 每连接读缓冲 4 KB，写缓冲 4 KB。
③ JSON 序列化复用 sync.Pool 的 buffer，避免每帧新分配。

R4

check 进程的瞬时内存 + 并发 apply

OOM

sing-box check 是独立进程，会完整加载配置（包括 rule_set），瞬时占用 30–45 MB。 如果它与正在运行的 core 叠加，再赶上一次订阅更新，256 MB 设备就会触发 OOM killer—— 而 OOM killer 通常先杀内存占用最大的 sing-box，表现为「保存配置后代理挂了」。

规避

① apply 全程持有互斥锁，杜绝并发校验。
② 校验前读 /proc/meminfo 的 MemAvailable，低于 48 MB 直接拒绝并提示稍后再试。
③ check 子进程设 GOMEMLIMIT=32MiB，并加 8s 超时。
④ 定时任务与手动保存共用同一把锁，不并行。

R5

check 通过 ≠ 能启动：五类运行时失败

启动失败

语法正确只代表 JSON 与字段合法。实际启动失败的高频原因：

  • 端口占用：旧 sing-box 未退干净，12345 / 9091 仍被 listen。
  • TUN 冲突：OpenWrt 已有 auto_route 或策略路由，创建 singbox0 失败。
  • 缺少内核模块：tproxy 需要 kmod-nft-tproxy，check 阶段完全检测不到。
  • cache.db 不可写：配置在只读分区，或目录属主不对。
  • nftables 表名冲突：重复 table inet singbox 导致规则下发失败。
规避

① 启动前跑预检：ss -ltn 探端口、nft list tables 查表、lsmod 查模块、试写目录。
② 启动后 3s 内请求 Clash API /version，失败即回滚上一快照并重启。
③ supervisor 崩溃重启限流 3 次 / 10 分钟，超限停止并告警，避免死循环拖垮整机。

internal/service/tproxy/probe.gogo
// Preflight 在写 nft 规则之前跑一遍，任何一项失败都不下发。
func Preflight(ctx context.Context, iface string, port int) error {
	if _, err := os.Stat("/sys/module/nft_tproxy"); err != nil {
		return fmt.Errorf("kmod-nft-tproxy missing")
	}
	if listen, _ := portInUse(port); listen {
		return fmt.Errorf("port %d already in use", port)
	}
	if ok, _ := tableExists(ctx, "inet", "singbox"); ok {
		// 幂等：先删旧表，避免重复定义
		if err := flushTable(ctx, "inet", "singbox"); err != nil {
			return err
		}
	}
	if avail := memAvailableMB(); avail < 48 {
		return fmt.Errorf("low memory: %d MB available", avail)
	}
	return nil
}

08明确不做

不做

  • 自定义路由语言（RoutingA 式方言）
  • 与官方 Dashboard 雷同的纯配置编辑器
  • 任何内置数据库，包括 SQLite
  • 前端解析 Geo 数据或全量日志
  • 在后端硬编码 sing-box 字段映射

改为

  • 原生 route.rules JSON + 图形化排序
  • 订阅一站式 + 透明代理一键开关
  • JSON 文件 + tmp → fsync → rename
  • 后端裁剪 + 2s 节流 + 50 行环形缓冲
  • 模板合并，字段由用户维护

理由很直接：每多一层抽象，就多一份与上游版本赛跑的维护成本。 sing-box 的配置格式仍在快速迭代，面板的价值在于把「重复的运维动作」变短， 而不是在它之上再造一门语言。

验收口径：在一台 256 MB 的 MT7981 上，同时跑 sing-box（redirect + 3 个 rule_set）、 dnsmasq 与面板，free -m 的 available 应始终 ≥ 40 MB； 连续执行 20 次「保存配置」不出现 RSS 单调上涨；断电重启后配置不损坏、快照可回滚。
